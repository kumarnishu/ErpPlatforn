# Shared cache

This building block stores only `UserId`, `TenantId`, `SessionId`, and boolean `TokenVersion`. Each session ID has one cache key, and `TryAddAsync` returns `false` when that key already exists instead of overwriting it. `AddSharedDistributedCaches()` uses in-memory storage for local development; production hosts can register a distributed provider such as Redis before registering the cache service. The duplicate check is serialized within one app process; `IDistributedCache` has no atomic add operation, so multi-instance deployments need a provider-specific atomic insert (for example, Redis `SET NX`) to prevent concurrent duplicate writes across instances.
