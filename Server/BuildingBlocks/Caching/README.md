# Shared cache

This building block stores only `UserId`, `TenantId`, `SessionId`, and boolean `TokenVersion`. Each session ID has one cache key, and `TryAddAsync` returns `false` when that key already exists instead of overwriting it. `AddSharedDistributedCaches(configuration)` uses Redis when `ConnectionStrings:Redis` is configured and otherwise falls back to in-memory storage. All APIs that validate the same sessions must use the same Redis instance. The duplicate check is serialized within one app process; `IDistributedCache` has no atomic add operation, so multi-instance deployments need a provider-specific atomic insert (for example, Redis `SET NX`) to prevent concurrent duplicate writes across instances.
